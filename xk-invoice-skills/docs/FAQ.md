# 常见问题与实战踩坑

以下多数来自真实批次处理（74 个文件、72 张票据、¥21,368.42）中踩过的坑。

## 识别环节

**Q：数电票发票号码识别成 18/19 位？**
A：数电票号码是 **20 位**，视觉模型容易漏掉连续 0 或连续相同数字（例如 `…693336` 读成 `…69336`）。发现位数不对，先把原图右上角号码区域裁出来放大 8–10 倍逐字符复核，**不要凭一次结果就补位或判定异常**。税号里的连续数字同理（`664641441` 易漏成 `66461441`）。

**Q：机票行程单识别失败？**
A：这类 PDF 常是纯图片、且尺寸超大（6900×4006）。先 `sips -Z 1600 <图>`（macOS）或等比缩小到 /tmp 再识别，**不要覆盖 tu/ 里的原图**。行程单金额口径是「票价 + 燃油附加费 + 民航发展基金」，不是增值税发票的「价税合计」。

**Q：滴滴电子发票金额算错了？**
A：滴滴票的排版把 `¥` 和数字分行，且 `¥14.89`（税额）、`¥510.95`（价税合计）混在一起。解析时两种模式都要覆盖：`¥数字` 和 `数字\n¥`，再取价税合计。**优先用 PDF 文本层提取**，比视觉识别更精确；纯图片才走视觉。

**Q：发现支付截图 / 重复发票怎么办？**
A：流水线会暂停报告，不会直接出表。常见处置：支付截图（云闪付/微信交易成功页）**不计入台账**；两个 MD5 完全相同的图片是同一张发票的两个副本，**只计一次**。原文件不删除，只从数据和归档里排除。

## 归类环节

**Q：文件夹名字和发票内容不一致？**
A：按**内容**归类，不按文件夹。真实案例：`图书/6422860003.pdf` 其实是电信服务发票 → 通信费；`滴滴/11010126_0052557770.PDF` 其实是停车占道非税票据 → 停车费。文件名里的数字也可能是业务流水号而不是发票号。

**Q：数码产品 / 办公用品发票没有对应科目？**
A：固定科目表里没有的，归到「其他」单列，由财务最终判定，不要硬塞进图书资料费。

**Q：停车非税票据为什么要单独处理？**
A：北京市非税收入统一票据不是增值税发票，按口径 `number` / `taxid` 留空、`category` 写「北京市非税收入票据」、归「停车费」。票据上可能印有缴款人统一社会信用代码，但那不等于增值税发票的购买方税号栏。

**Q：`--scan` 提示「图片总数与数据条数不一致」？**
A：脚本只扫描各子目录的 `tu/`。若某张图片存在子目录根部（如 `餐饮/发票文件1.png`）而没进 `tu/`，就会差 1 张，属于正常差异，不是遗漏。真正要查的是：是否有发票没识别、或一张发票被计了两次。另外重复文件、支付截图被排除也会造成差额。

## 出表与归档

**Q：金额精度不对 / Excel 合计显示异常？**
A：JSON 里 `amount` 必须是**字符串**（`"30.30"`），脚本内部用 `Decimal` 累加，合计写静态数值而不是公式。用 float 直接相加会出分位误差；写公式在没装 Excel 的预览器里会显示空白。

**Q：`organize_invoices.py --extra` 重跑后，「其他」目录里还留着旧副本？**
A：脚本只拷贝、不清理上一轮结果。重跑前先把 `invoice/` 下的归档副本清一遍（**原始图片都在原目录，别动**），再带 `--extra` 重跑，否则会重复。

**Q：哪些图片会落到「其他」需要人工补映射？**
A：文件名不含发票号的（`滴滴电子发票A.jpg`、`微信图片_*.jpg`）、文件名数字是流水号或行程单号的、以及非税票据。做法：先不带 `--extra` 跑一遍，对清单里的图片逐张视觉识别真实发票号，写成 `{"文件名.jpg": "发票号码"}` 的 JSON，再 `--extra 映射.json` 重跑。

**Q：非税票据没有发票号，怎么归档到停车费？**
A：`--extra` 依赖号码映射，对 `number` 为空的非税票据无效。归档完成后手动把该图片从 `invoice/其他/` 移到 `invoice/停车费/` 即可，不改台账。

**Q：PDF 转出来的 JPG 是全白的？**
A：用了 `sips` 或 `qlmanage`。文字型矢量 PDF 会渲染成空白，必须用 PyMuPDF（`pdf2jpg.py`）。自检方法：`tu/` 下小于 10KB 的 JPG 基本都是空白图，正常发票图一般大于 100KB。

## 安装环节

**Q：装到别的电脑上，AIGC 合规标识写不进去？**
A：`aigc_label.py` 是 WorkBuddy 内置插件脚本，不在本仓库。非 WorkBuddy 环境跳过该步即可，台账功能不受影响；或设 `AIGC_LABEL_SCRIPT` 指向自己的实现。见 [INSTALL.md](INSTALL.md)。

**Q：改了技能但助手还是用旧逻辑？**
A：`install.sh` 默认跳过已存在的技能，要 `./install.sh --force`，然后重启 WorkBuddy 重新加载技能。

**Q：能不用 WorkBuddy，只跑脚本吗？**
A：可以。三个 Python 脚本都是标准库 + PyMuPDF/openpyxl，命令见 [INSTALL.md 方式 C](INSTALL.md)。只是「逐张视觉识别 + 暂停核对」这一步需要由人或其他视觉模型完成。
