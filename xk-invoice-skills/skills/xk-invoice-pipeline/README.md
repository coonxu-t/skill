# xk-invoice-pipeline 使用说明与设计文档

发票报销台账**全链路一键处理**的总入口。本技能本身不含脚本，靠编排三个下游 xk 技能完成任务。

## 一、这是什么

给定一个发票目录（可能含多个子目录、历史遗留图片），自动走完完整流水线，产出：

1. 各子目录的 `tu/` 图片（PDF 已转 JPG）
2. 一份可交财务的报销台账 Excel（`发票报销台账_报销口径.xlsx`）
3. （可选）按报销科目归档的 `invoice/<科目>/` 图片目录

## 二、一条命令怎么用

对助手说：

> 处理 `/Users/xxx/Desktop/202610` 目录的发票出报销台账

助手会按 SKILL.md 里的流程自动执行。要额外归档图片，追加一句：

> 顺便按科目归档发票图片

## 三、完整流水线（五步）

```
PDF/图片
  └─ ① xk-pdf-to-jpg    递归把各子目录 PDF 转 JPG 到各 tu/（PyMuPDF）
  └─ ② xk-invoice-ocr-summary  逐张识别 5 字段 + 查重 + 抬头税号核对
       └─ 发现问题（重复/税号不一致/抬头不一致/非发票）→ 暂停报告
  └─ ③ xk-invoice-ledger  按报销口径归类 → 出台账 Excel（--scan 交叉校验）
  └─ ④ 写入 AIGC 合规标识
  └─ ⑤ (可选) organize_invoices.py 按科目归档图片到 invoice/
```

### 步骤详解

| 步 | 做什么 | 关键命令 | 关键点 |
|---|---|---|---|
| ① | 摸清目录 + 转图 | `pdf2jpg.py <目录>` | 机票行程单可能 6900×4006，识别前 `sips -Z 1600` 缩小 |
| ② | 逐张识别 | 视觉模型逐张读 5 字段 | 发现问题先暂停；税号连续数字易漏读需放大复核 |
| ③ | 出台账 | `build_ledger.py --scan <目录> <json> <xlsx> <抬头>` | 关注「图片总数 vs 数据条数」差异 |
| ④ | 合规标识 | `aigc_label.py <xlsx> --platform WORKBUDDY` | 新生成工作簿必须 |
| ⑤ | 归档图片 | `organize_invoices.py <json> <目录> [--extra <映射>]` | 先跑一遍看「待归类」，补映射重跑 |

## 四、固定口径（本项目长期有效）

| 项 | 值 |
|---|---|
| 购买方抬头 | 北京云测信息技术有限公司 |
| 购买方税号 | `91110105664641441Q` |
| 报销科目 | 餐饮费 / 住宿费 / 交通费-火车票 / 交通费-网约车 / 交通费-机票 / 交通费-油费 / 图书资料费 / 通信费 / 停车费 |
| 归类原则 | 按发票**内容**归类，不按所在文件夹 |
| 停车费 | 北京市非税收入票据，无税号，单列 |
| 机票 | 行程单（票价+基金+燃油）或机票款电子发票，都归「交通费-机票」 |
| 金额 | 全程 Decimal，amount 用字符串，合计写静态数值不写公式 |

## 五、数据流（三脚本如何衔接）

```
视觉识别（②）
   │  产出 JSON（纯数组，5 字段 + 可选 title）
   ▼
发票数据.json
   ├─→ build_ledger.py（③）  → 发票报销台账_报销口径.xlsx
   └─→ organize_invoices.py（⑤）→ invoice/<科目>/*.jpg
```

**JSON 统一格式**（全系列唯一标准）：

```json
[
  {"content": "*生产生活服务*餐费", "number": "2611200000...", "category": "电子发票（普通发票）", "taxid": "91110105664641441Q", "amount": "296.00"}
]
```

- 纯数组 `[...]`，每项 5 个必填字段（content/number/category/taxid/amount）+ 可选 title。
- 抬头统一由命令行第 5 个参数传，不逐张冗余填 title。
- 停车费 `taxid` 填空串、`category` 写「北京市非税收入票据」。

## 六、常见坑汇总

1. **sips 转 PDF 出空白图** → 必须用 PyMuPDF（pdf2jpg.py）。
2. **机票行程单超大图** → 6900×4006，先 `sips -Z 1600` 缩小再识别，识别后删除临时 `_small.jpg`。
3. **OCR 税号漏读连续数字** → `664641441` 漏成 `66461441`，疑似异常先放大复核。
4. **数电票号码 20 位** → OCR 易漏成 18/19 位，逐字符复核。
5. **图书目录混电信发票** → 按内容归通信费，不按文件夹。
6. **图片数 vs 数据条数差异** → 通常是：多张图对应一条数据（如发票+小票辅助凭证）、或临时 `_small.jpg` 未清理。
7. **同一张发票两张图** → 如「餐饮大额」有发票本体 + 转账/小票，都归档但金额只计一次。

## 七、如何修改迭代

- **改报销科目/归类规则** → 改 `xk-invoice-ledger/scripts/build_ledger.py` 里的 `classify()` 和 `CAT_ORDER`（organize_invoices.py 会自动复用）。
- **改归档图片的兜底规则** → 改 `organize_invoices.py` 的 `KEYWORD_RULES` / `DIR_CAT`。
- **改识别字段口径** → 改 `xk-invoice-ocr-summary/references/识别规范.md` 和 `summarize.py` 的 `validate()`。
- **改固定抬头/税号** → 本文件「固定口径」+ pipeline SKILL.md 同步改。
- **新增下游技能** → 在本文件「完整流水线」和「三个下游技能」表里登记。
