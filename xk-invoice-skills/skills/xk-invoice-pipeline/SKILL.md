# 发票报销台账全链路一键处理

这是发票处理的**总入口编排技能**。它自己不写代码，而是把三个已有 xk 技能串成一条确定性流水线，确保每次处理发票目录时步骤不漏、口径一致。

## 这条链路做什么

给定一个发票目录（可能含多个子目录），走完四步，最终产出一份可交财务的报销台账 Excel + 按科目归档的发票图片：

```
PDF/图片 → (1)转JPG → (2)识别+核对 → (3)按报销口径出台账 → (4)按科目归档图片
```

## 三个下游技能

| 步骤 | 技能 | 作用 |
|---|---|---|
| ① 转图片 | `xk-pdf-to-jpg` | 递归把各子目录 PDF 转 JPG，存各子目录 `tu/`，用 PyMuPDF（勿用 sips，会出空白图） |
| ② 识别核对 | `xk-invoice-ocr-summary` | 逐张视觉识别 6 字段 + 查重 + 抬头税号核对 |
| ③ 出台账 | `xk-invoice-ledger` | 按报销口径归类，遍历目录交叉校验，出 Excel；并用 `organize_invoices.py` 按科目归档图片 |

## 标准流程（必须按顺序，不可跳步）

### 第 1 步：摸清目录

```bash
find <目录> -maxdepth 2 -type d | sort
find <目录> -type f \( -iname "*.pdf" -o -iname "*.jpg" -o -iname "*.jpeg" -o -iname "*.png" \) | sort
```

- 统计 PDF 数和已有 JPG（特别注意「刘芊/tu」这类历史遗留图片目录，也要纳入）。
- 注意子目录里已有的 `图`/`图片`/`定额图`/`转账` 等目录，**不要动**，只操作各子目录的 `tu`。

### 第 2 步：转 PDF 为 JPG（有 PDF 才做）

```bash
python3 <skills>/xk-pdf-to-jpg/scripts/pdf2jpg.py "<目录>"
```

- 输出到各子目录的 `tu/`，尺寸 = PDF 原始 Point 尺寸 × 2。
- 转完自检：空白图文件 <10KB，正常图 >100KB。若有空白，说明渲染失败，需查 PyMuPDF 是否可用。

### 第 3 步：逐张识别 + 核对（发现问题就暂停）

对 `tu/` 下所有 JPG 逐张用视觉模型识别 6 个字段：
- 发票号码、发票类别、购买方抬头、购买方税号、项目名称、价税合计金额。

**核对规则（发现问题必须暂停报告，不继续出表）**：
- 重复发票（号码重复）
- 抬头不一致
- 税号不一致
- 非发票文件（支付截图、非税票据、机票行程单等——非税票据和行程单本身要识别出来，但要在台账里单独归类）

**常见识别坑**：
- 机票行程单尺寸可能超大（6900×4006），识别失败时先用 `sips -Z 1600` 缩小再识别。
- OCR 税号易漏读连续数字（如 `664641441` 漏成 `66461441`），疑似不一致先放大逐字符复核，确认是误差还是真问题。
- 数电票发票号码是 20 位，OCR 易漏成 18 位，逐字符复核。

**全部通过才进入第 4 步。**

### 第 4 步：按报销口径出台账

1. 把识别结果整理成 JSON（`amount` 用字符串）：
   ```json
   {"content": "*餐饮服务*餐饮费", "number": "26112000001956652561", "category": "电子发票（普通发票）", "taxid": "91110105664641441Q", "amount": "30.30"}
   ```
   - 非税票据（停车费）：`number`/`taxid` 空字符串，`category` 写「北京市非税收入票据」。

2. 运行 ledger（目录遍历模式，交叉校验）：
   ```bash
   python3 <skills>/xk-invoice-ledger/scripts/build_ledger.py --scan "<目录>" "<数据.json>" "发票报销台账_报销口径.xlsx" "北京云测信息技术有限公司"
   ```
   - 关注「图片总数 vs 数据条数」是否一致，不一致要查原因（遗漏或多计）。

3. 写入 AIGC 合规标识：
   ```bash
   python3 <workbuddy-sheet-generation>/scripts/aigc_label.py "发票报销台账_报销口径.xlsx" --platform WORKBUDDY
   ```

4. 呈现文件并汇报：各报销科目张数 + 金额、总计、需人工注意的点。

### 第 5 步（默认执行）：按科目归档发票图片

**默认自动执行，无需用户另外要求**。在第 4 步出完台账后，紧接着按报销科目把发票图片归档到 `invoice/`：

```bash
python3 <skills>/xk-invoice-ledger/scripts/organize_invoices.py "<数据.json>" "<目录>"
```

- 先在 `<目录>` 下生成 `invoice/`，按报销科目建子目录，把每张发票图片**拷贝**到对应子目录。
- **推荐流程**：先不传 `--extra` 跑一遍，脚本会打印「待人工归类」清单（文件名不含发票号、或文件名数字是流水号/行程单号的图片）；对这些图片用视觉识别出真实发票号，写成 JSON 映射（`{"文件名.jpg": "发票号码"}`），再 `--extra <映射.json>` 重跑即可全部归位。
- 结束打印各科目张数，确认与台账张数一致，仍有「其他」会给待核对清单。

> **注意**：第 5 步是默认动作，不是可选。台账和归档图片应作为同一批交付物一起产出，不要在第 4 步后停下等用户提醒。

## 固定口径（本项目约定，长期有效）

- **购买方抬头**：北京云测信息技术有限公司
- **购买方税号**：`91110105664641441Q`
- **报销科目**：餐饮费 / 住宿费 / 交通费-火车票 / 交通费-网约车 / 交通费-机票 / 交通费-油费 / 图书资料费 / 通信费 / 停车费
- **归类原则**：按发票实际内容归类，不按所在文件夹（如「图书」夹里混电信发票归通信费；「滴滴」夹里混高铁票归火车票）。
- **停车费**：北京市非税收入票据，非增值税发票、无税号，单列。
- **机票**：可能是「行程单」（票价+基金+燃油）或「机票款」电子发票（价税合计），都归「交通费-机票」。
- **金额**：全程 Decimal，禁止 float 直接累加，合计写静态数值不写公式。

## 完成后

- 生成台账 `发票报销台账_报销口径.xlsx`。
- 询问用户是否删除中间数据文件 `发票数据.json`（默认用户可能想删，但也可能想留着重跑，**先问**）。
