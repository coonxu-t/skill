# 发票图片字段识别指引

从发票图片（`.jpg`/`.png`/`.pdf` 等）中提取以下字段时，按此规范执行，确保字段口径一致。

## 必提取字段（每张发票 5 项，title 可选）

| 字段 | JSON key | 说明 |
|---|---|---|
| 发票内容 | `content` | 发票右上「货物或应税劳务名称」，如 `*生产生活服务*餐费`，保留 `*` 标签 |
| 发票号码 | `number` | 发票右上角的号码，逐字符读，数字与字母严格区分（0/O、1/I、Q、Y） |
| 发票类别 | `category` | 如 `电子发票（普通发票）`、`增值税专用发票`、`增值税普通发票` |
| 购买方税号 | `taxid` | 购买方「纳税人识别号 / 统一社会信用代码」，18 位，含字母与数字 |
| 价税合计 | `amount` | 发票底部「价税合计（小写）」，**以字符串保存**（如 `"296.00"`）避免浮点误差 |
| 购买方抬头 | `title` | 购买方「名称」栏（**可选**；本批发票抬头统一时可不写，出表时靠命令行参数传入） |

> **口径约定（全 xk 系列统一）**：数据文件一律是**纯数组 `[...]`**，每项 5 个必填字段 + 1 个可选字段；抬头统一由「期望抬头」参数传入，不逐张冗余填写。

## 识别规范

1. **金额一律以「小写价税合计」为准**，不以大写为准；若只有大写，按大写换算。
2. **税号/号码逐字符核**：遇到易混字符（0/O、1/I/l、Q/2、Y/V、5/S）时放大图片复核，必要时与「统一社会信用代码」栏交叉验证。
3. **同一批发票核对抬头与税号是否一致**：若个别发票税号与其余不同，如实标注，不擅自修正。
4. **区分发票与凭证**：支付成功截图 / 交易凭证**不是发票**，无发票号码、税号、价税合计等要素，应单独标注「非发票」，不计入汇总。识别前先判断图片类型。
5. **非增值税凭证的字段口径**：
   - 停车费（北京市非税收入票据）：`number` 填票据号码、`taxid` 填空字符串 `""`、`category` 写「北京市非税收入票据」。
   - 机票行程单：`number` 填电子客票号码、`category` 写「航空运输电子客票行程单」，`amount` 取「票价+民航发展基金+燃油附加费」的合计。

## 输出数据格式

识别完成后，将结果写入一个 JSON 文件（**纯数组**），供 `summarize.py` / `build_ledger.py` 消费：

```json
[
  {
    "content": "*生产生活服务*餐费",
    "number": "26112000004363116496",
    "category": "电子发票（普通发票）",
    "taxid": "91110105664641441Q",
    "amount": "296.00"
  }
]
```

## 常见坑

- **图片分辨率低** → 税号/号码末段易错，务必放大复核，结论里写明「建议人工复核原始票据」。
- **多图同金额** → 金额相同不代表重复，重复判定只看**发票号码**。
- **子目录/嵌套目录** → 需递归遍历目录，不要漏掉子文件夹里的发票。
- **税号连续数字易漏读** → 如 `664641441` 漏成 `66461441`，疑似异常先放大复核。
