# xk-invoice-ocr-summary 设计文档

发票图片批量识别与汇总。这是全链路的**识别端**，产出结构化 JSON 数据，供下游 `xk-invoice-ledger` 消费。

## 一、定位与边界

| 项 | 说明 |
|---|---|
| 做什么 | 逐张视觉识别发票 5 字段 + 查重 + 抬头税号核对 + 分类统计 + 出 Excel 报告 |
| 不做什么 | 不填开/作废/冲红发票（只读）；**不负责**按报销口径归类（那是 ledger 的活） |
| 产出 | `发票数据.json`（供 ledger）+ `发票汇总报告.xlsx`（自查用） |

## 二、识别流程

```
列文件（递归，含子目录）
  └─ 逐张视觉识别 5 字段
       └─ 先判断：是不是发票（支付截图/交易凭证 = 非发票，单独标注）
  └─ 结构化 → 发票数据.json（纯数组）
  └─ summarize.py → 查重 + 抬头税号核对 + 分类统计 + 出 Excel
```

## 三、字段口径（与全系列统一）

纯数组 `[...]`，每项：

| 字段 | key | 必填 | 说明 |
|---|---|---|---|
| 发票内容 | content | ✅ | 保留 `*xx*` 标签，如 `*生产生活服务*餐费` |
| 发票号码 | number | ✅ | 逐字符读，区分 0/O、1/I、Q、Y |
| 发票类别 | category | ✅ | 普通发票/专用发票/行程单/非税票据 |
| 购买方税号 | taxid | ✅ | 18 位；非税票据填空串 `""` |
| 价税合计 | amount | ✅ | **字符串**存，取小写金额 |
| 购买方抬头 | title | 可选 | 统一时省略，靠命令行参数传 |

> 详见 `references/识别规范.md`。示例见 `assets/示例发票数据.json`。

## 四、summarize.py 逻辑

```bash
python3 summarize.py 数据.json 输出目录 [期望抬头] [期望税号]
```

- `load()`：兼容 `{"invoices":[...]}` 和 `[...]` 两种（历史遗留），推荐用纯数组。
- `validate()`：校验 5 个必填字段；`title` 缺失时用「期望抬头」回填。
- 高精度 Decimal 累加 + 打印逐步累加中间结果。
- 按号码查重、按抬头/税号核对（传期望值后标 ✅/⚠️）。
- 分类统计按 `*xx服务*` 标签归类（**注意**：这是粗分类，报销口径归类在 ledger 的 classify()）。

## 五、与下游的衔接

```
发票数据.json（本技能产出）
  └─→ xk-invoice-ledger/scripts/build_ledger.py      按报销口径出台账
  └─→ xk-invoice-ledger/scripts/organize_invoices.py 按科目归档图片
```

**关键**：本技能的 `summarize.py` 只做「识别 + 粗分类 + 核对」，**报销口径归类**统一由 ledger 的 `classify()` 决定，避免两处归类规则不一致。

## 六、发现问题的处理（暂停机制）

识别命中以下任一，**暂停报告，不继续出表**：
1. 重复发票（号码重复）
2. 税号不一致
3. 抬头不一致
4. 非发票文件（支付截图/交易凭证）

**易错提醒**：税号连续数字易漏读（`664641441` → `66461441`），疑似异常先放大复核，不凭一次 OCR 下结论。
