# 发票图片批量识别与汇总

## 这个技能做什么

把一目录发票图片（含子目录）变成一份**可报账的发票台账**：识别每张票的关键字段，用高精度数值计算汇总，检查重复与抬头/税号一致性，按类别统计，最后产出 Excel 报告。

固定输出一份：

| 产物 | 内容 |
|---|---|
| `发票汇总报告.xlsx` | 4 个 Sheet：全部发票明细（含购买方税号）、分类统计、汇总计算过程、核对与说明 |

核心方法：**逐张识别 → 结构化 → 高精度累加并保留中间步骤 → 交叉核对（重复/抬头/税号）→ 出表**。

## 何时使用

- 用户给出一个发票图片目录，要求「统计金额 / 汇总 / 价税合计」
- 用户要求「查重发票」「核对抬头/税号是否一致」「按类别统计」
- 用户要求「生成发票台账 / 发票表格」（字段含发票内容、号码、类别、税号、金额等）
- 需要报账前对一批发票做合规预检

不适用：单张发票的填开、作废、冲红等税务操作（本技能只读不写，不改任何发票原件）。

## 标准流程（四步）

1. **列文件**：递归遍历目标目录，列出所有发票图片（`.jpg/.jpeg/.png/.pdf` 等）；注意子目录（如「大额」）里的文件也要覆盖。
2. **逐张识别**：对每张图片用图像识别（ViewImage / 视觉模型）提取 5 个字段——`content`（发票内容）、`number`（发票号码）、`category`（发票类别）、`taxid`（购买方税号）、`amount`（价税合计）。抬头 `title` 可选（本批统一时靠命令行参数传）。识别规范见 `references/识别规范.md`。
   - **先判断图片类型**：支付截图 / 交易凭证不是发票，单独标注「非发票」，不计入汇总。
   - 易混字符（0/O、1/I、Q/Y）放大复核；金额一律取「小写价税合计」。
3. **结构化**：把识别结果写成 JSON（纯数组，格式见 `references/识别规范.md` 或 `assets/示例发票数据.json`），`amount` 用字符串存。
4. **计算与出表**：调用 `scripts/summarize.py` 完成高精度汇总、查重、抬头税号核对、分类统计，并生成 Excel。

```bash
python3 <skills>/xk-invoice-ocr-summary/scripts/summarize.py 发票数据.json 输出目录 [期望抬头] [期望税号]
```

`summarize.py` 自动完成并打印：
- 逐笔金额 + 汇总总额（Decimal 高精度，保留 2 位小数）
- **汇总中间步骤**（第 1 步…第 N 步，逐步累加，便于复核）
- 重复发票检查（按号码）
- 抬头 / 税号分布核对（传入期望值后会自动标 ✅/⚠️）
- 分类统计（按 `*xx服务*` 标签归类）

## 汇报时必须讲清楚的四件事

1. **总额与张数**：有效发票张数、价税合计总额（大写）。
2. **重复结论**：是否重复，重复则点出具体号码。
3. **抬头/税号一致性**：是否全部一致；若个别发票税号不同（如某张是 `91110108MA018UFQ1Y` 而其余是 `…664641441Q`），**如实标注并建议人工复核原始票据，不擅自判定**。
4. **非发票文件**：目录里的支付截图 / 交易凭证要单独说明，不计入汇总。

## 发现问题的处理（重要）

识别过程中若命中以下任一「问题」，**必须暂停并向用户报告，不要继续出表**：

1. **重复发票**：同一发票号码出现 ≥2 次。
2. **税号不一致**：存在不同购买方税号。
3. **抬头不一致**：存在不同购买方抬头。
4. **非发票文件**：目录里混入支付截图 / 交易凭证等非发票。

若全部核对通过（抬头税号一致、无重复），才进入下一步：交给 `xk-invoice-ledger` 遍历目录出报销台账。

**易错提醒**：OCR 偶尔会把税号中的连续数字读错（如 `664641441` 漏读成 `66461441`）。发现税号疑似异常时，**先放大复核原始图片**再下结论，不要凭一次 OCR 结果就报「税号不一致」。

## 底线

- 只读不写：不改动、不删除任何发票原图与原始文件。
- 金额高精度：一律用 `Decimal`（或等价精确类型）计算，`amount` 用字符串传入，禁止用 float 直接累加导致精度误差；结果保留 2 位小数。
- 识别不确定就标注「建议人工复核」，不臆造税号或金额。
