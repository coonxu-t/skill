# Testin 培训 PPT 制作

当用户需要一份真正像 Testin 内部培训或客户培训材料的 PPT 时使用本 skill。目标不是做一个泛蓝色模板，而是做出 Testin 的版式、字体、标题栏、logo 和留白气质。

## 必须遵守的工作流

- 使用 `ppt-training-deck-maker` 的工作流，并参考 `presentations` skill 的 PowerPoint 实现细节。
- 使用 JavaScript ES modules 和 `@oai/artifact-tool`。
- 不要使用 `python-pptx`。
- 交付前必须逐页渲染最终 PPT。
- 如果覆盖重建同一个输出 PPTX，必须先完成 PPTX 导出，再运行渲染检查。不要对同一个目标文件并行执行构建和渲染。

## 输入与默认规则

1. 用户提供的 Markdown、大纲、PDF 笔记或初稿 PPT 是故事内容来源。
2. 如果用户提供 Testin 参考模板，优先使用用户提供的模板。
3. 如果用户没有提供模板，默认使用 [assets/Testin模板.pptx](./assets/Testin模板.pptx)。
4. 默认输出本地 `.pptx`，除非用户明确要求其他格式。

## 制作顺序

1. 先检查选定的 Testin 模板，再开始写内容和排版。
2. 排版前必须阅读 [references/testin-template-spec.md](./references/testin-template-spec.md)。
3. 保留源内容的大纲顺序，但要改写成简洁的中文培训页表达。
4. 前三页必须绑定 Testin 模板页族：
   - 第 1 页：封面页
   - 第 2 页：目录页
   - 第 3 页：蓝色分节页
5. 目录页和分节页的字体必须与检查到的 Testin 模板完全一致。不要使用近似字号；应复用继承的模板文本框，或复制其 run 级别的 `typeface`、`fontSize`、`bold`、颜色、对齐方式和坐标。
6. 正文页标题字体必须与检查到的 Testin 模板完全一致。默认 `Testin模板.pptx` 的正文标题为 `微软雅黑`、16pt、加粗，并放在参考文件规定的标题坐标上。
7. 正文页的 Testin 版式组件必须保持稳定：
   - 左侧标题蓝色竖条
   - 正文标题框
   - 右上角 Testin logo
   - 正文背景和水纹

## 字体与版式规则

- 所有新写入文本都使用 `typeface: "微软雅黑"`。不要依赖 `fontFace`。
- 所有字号必须严格使用本 skill 和参考规格文件列出的 PowerPoint 目标字号。不要在生成脚本中自行估算、换算或临时新增字号；尤其不要用 artifact-tool 的 numeric `fontSize` 当作 pt 值，因为 numeric `fontSize` 是 px，可能导出成 13.5pt 等非规范字号。
- 写入文本时优先使用明确的 pt 单位，例如 structured run 的 `fontSize: "18pt"`，或使用能明确表达 PowerPoint 点数的 API。目录项、分节标题、正文标题等模板固定文本必须复制模板 run 的真实字号，不得用 px 近似值代替。
- 正文页内容字号保持在参考文件给出的 Testin 正文字号范围内。
- 封面、目录、分节页视为固定模板页族，字体大小、位置和对齐必须严格匹配模板。
- 目录页和分节页必须检查模板真实文本 run，并复现精确样式。默认 `Testin模板.pptx` 中，目录标题是 `微软雅黑` 32pt 加粗白字，目录项是 `微软雅黑` 18pt，分节页标题是 `微软雅黑` 32pt 加粗白字。
- 正文页必须保持标题坐标和标题 run 样式完全一致，但正文内容区域可以灵活排版。默认 `Testin模板.pptx` 中，正文标题是 `微软雅黑` 16pt 加粗。
- 正文页 Testin 版式组件不能漂移：标题竖条、标题行、logo 位置和背景水纹要在各正文页保持一致。
- 连续页面内容类型不同时，不要重复使用完全相同的卡片轮廓。
- 少用密集项目符号，优先使用更少、更有力的信息块。
- 大标题尽量保持单行。如果标题换行，先缩短标题或加宽文本框，再考虑缩小字号。

## 构图建议

- 策略、路径类页面：使用横向推进结构，不要堆叠拥挤节点。
- 团队、使命类页面：使用平衡的双栏、2x2 或 3 列布局，一个主强调块即可，其余信息保持克制。
- 定义、总结类页面：保留一个主视觉/主指标块，再配一到两个辅助说明块。
- 优先使用平面矩形、线条、分隔条、浅色块，少用圆角通用卡片。整体要像 Testin，而不是素材网站蓝色培训模板。
- 如果使用图标，图标要小而功能化，只辅助层级，不成为页面主视觉。
- 不要添加源内容中没有的装饰性结束口号。

## 质量检查

1. 将最终 PPTX 逐页渲染为 PNG。
2. 检查页数准确、备注为空、没有未处理占位符。
3. 检查所有新写入文本都是 `微软雅黑`。
4. 检查目录页和分节页文本 run 与模板检查结果完全一致，包括 `typeface`、`fontSize`、`bold`、颜色、对齐方式和坐标。
5. 检查正文页标题文本 run 与模板检查结果完全一致，包括 `typeface`、`fontSize`、`bold`、颜色、对齐方式和坐标。
6. 检查正文页内容字号保持在参考文件给出的 Testin 正文字号范围内；这个检查不包含正文标题。
7. 检查导出的 PPTX/XML 或 layout 结果，确认不存在由 px 换算产生的非规范字号，例如正文内容或目录项出现 `13.5pt`、`10.5pt` 等未列入参考规格的字号时必须修正生成脚本并重新导出。
8. 扫描是否有模板旧案例文本残留。
9. 至少目视检查封面、目录、分节页，以及所有内容密集的正文页。
10. 如果渲染图看起来比脚本或 XML 旧，优先怀疑渲染顺序问题，按“先导出 PPTX、再渲染”的顺序重新执行。

## 交付

- 只返回最终 `.pptx` 路径/链接和简短质量检查摘要。
- 除非用户要求，不要返回临时文件、渲染图、layout JSON 或草稿说明。
